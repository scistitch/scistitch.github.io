Workflow automation

Makim

Give recurring tasks a shared, documented interface.

Released · ongoing development

Created by Ivan; ongoing development with the project community.

  • Python
  • YAML
  • Jinja2
  • CLI design
  • CI workflows
Makim website & documentationMakim source
The problem
Build, test, and data-processing commands often end up scattered across scripts, notebooks, and CI configuration. New contributors have to reconstruct how to run them.
The approach
Define tasks, arguments, dependencies, and scoped environments in YAML. Generate command-line help from those definitions and use conditional dependencies and parameter matrices to organize repeatable workflows.
Where this experience helps
Useful when a small team needs a consistent way to run local development, research jobs, and CI tasks.

Container workflows

Sugar

Make container configurations easier to run and maintain.

Released · ongoing development

Created by Ivan; ongoing development with the project community.

  • Python
  • Docker Compose
  • YAML
  • Podman (experimental)
Sugar documentationSugar source
The problem
Working across several container stacks means remembering Compose files, environment files, service selections, and repeated command-line options. Wrapper scripts can multiply across projects.
The approach
Keep those choices in named YAML profiles and expose them through a consistent CLI over Compose. Separate configuration from routine commands; Podman support remains experimental.
Where this experience helps
Useful when development and testing need different container setups without another set of custom scripts for each environment.

Compilers & scientific computing

Arx ecosystem

Explore a modular path from typed source code to native data processing.

Experimental · pre-production

Ivan’s ongoing work across the language, compiler libraries, and supporting tools.

  • Python
  • LLVM
  • C++
  • Apache Arrow
  • Type systems
Arx ecosystem statusArx source
The problem
A language for scientific data needs more than a parser: it needs type analysis, code generation, data interoperability, packaging, documentation, and tools for people to use it.
The approach
Separate the language frontend (Arx), shared syntax model (ASTx), and analysis and LLVM backend (IRx). Use Apache Arrow for native data containers, with related tools for projects, notebooks, documentation, and scientific libraries.
Where this experience helps
Relevant to custom languages, code generation, native data integration, and research prototypes. The ecosystem is still evolving; component readiness varies.
Explore the Arx ecosystem components

Core packages now live in the Arx monorepo. The former standalone ASTx and IRx repositories and the earlier C++ compiler are archived. Related tools have their own release cycles and limits.

Health research software

HiperHealth

Structure AI-assisted workflows so their steps and data can be inspected.

In development

Ivan’s ongoing work on the open-source clinical workflow library.

  • Python
  • Pydantic
  • Parquet
  • SQLAlchemy
  • LLM integration
HiperHealth documentationHiperHealth source
The problem
Health research workflows combine information arriving at different times, document extraction, and AI-generated suggestions. A single prompt makes those steps difficult to separate and examine.
The approach
Compose a Python pipeline from independent stages and skills. Use typed schemas and resumable Parquet sessions to retain interaction history, alongside document extraction and de-identification tools.
Where this experience helps
Relevant to staged AI integrations, structured data collection, and inspectable research workflows. This entry describes software engineering in progress, not validated clinical outcomes.

Open education & learning tools

FreeCampus

Keep learning materials and interactive exercises reusable.

Public materials · learning app in progress

Led by Ivan; ongoing work on learning materials, shared tools, and a learning app for the LMS.

  • Python
  • Jupyter
  • JSON
  • Quarto
  • MkDocs
FreeCampus coursesFreeCampus Tools sourceFreeCampus repositories
The problem
Course content, notebook exercises, and web quizzes can drift apart when each format is maintained separately. Educators need a practical way to publish and revise materials together.
The approach
Develop open course repositories and shared Python quiz models, with JSON export for web renderers and widgets for Jupyter and Colab. A separate learning app for the LMS is in progress.
Where this experience helps
Useful for education teams connecting content publishing, interactive exercises, and reusable software. Public materials and tools can be inspected now; the learning app is still being developed.
